# Agent compatibility

Expanded the tested targets to Codex 0.169.0 and Claude Code 2.1.323, with Codex 0.168.0 in CI. Claude in-session saves also needed to recognize a completed assistant response when the current prompt has not been flushed, preventing the preceding completed turn from being dropped. Codex resume can persist settings, and native revert may write a second settings record. Import now retains native snapshot metadata and restores archived settings and continuation together in one atomic write under the thread writer lock, keeping ordinals and reference boundaries aligned without changing pre-existing local histories.

Regression coverage checks archived settings and continuation preservation, rejects unknown generated records and mismatched native history boundaries, and protects modified or open snapshots. The active-session E2E checks the lock diagnostic and unchanged rollout bytes. Claude tests cover queued prompts separated by metadata, pending follow-ups during tool use, subagent completion, and follow-ups interleaved with a finishing turn. Native transfer tests passed on Codex 0.167.1, 0.168.0, and 0.169.0. The busy-session E2E probe uses its own home so native resume metadata does not interfere with the independent fast-forward test.

Validation: `make check` passed with required native E2E on Codex 0.169.0 and Claude Code 2.1.323. The full native E2E suite also passed on the minimum-supported pair, Codex 0.165.0 and Claude Code 2.1.317; native Codex transfer also passed on 0.167.1 and 0.168.0. A private real-archive import and interactive resume succeeded in an isolated provider home without overwriting existing histories. No release was published.
