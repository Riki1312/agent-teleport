# Codex imports with conflicting histories

Implemented an explicit copy mode for normal Codex imports. The Codex adapter chooses stable IDs for conflicting incoming histories and rewrites provider identity fields without altering recorded text. Ordinary import, replacement, and isolated import retain their existing entry points.

The native rehearsal exposed two revert cases. A fork export now retains the first removed turn's boundary record when a reverted ancestor needs replay. Import checks for that boundary before mutation. A retry accepts later local records on an earlier rollout object when the already replayed revert references the same cutoff.

Synthetic tests cover preserving an existing ancestor, planning without writes, stable IDs across imports, and replay of reverted and spawned threads. Repository `open` and `status` share import's mapping. Identity rewriting only matches provider fields at their structural JSON positions, and planning keeps unchanged rollout bytes by reference. The focused native tests pass on Codex 0.167.1 and 0.170.0, and the existing two-home transfer passes on 0.170.0. See [the tests](../../test/e2e/copy_test.go) and the [architecture](../../ARCHITECTURE.md#copy-conflicting-histories-into-the-current-profile).

The full local `make check` passed, including lint, unit and end-to-end tests, Markdown formatting, and whitespace checks.
